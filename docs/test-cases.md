# Тест-кейсы: API авторизации DummyJSON

Документация: https://dummyjson.com/docs/auth
Тестовый пользователь: `emilys` / `emilyspass`

## POST /auth/login — вход

### TC-1. Вход с корректными логином и паролем
**Данные:**

POST /auth/login, тело `{"username":"emilys","password":"emilyspass"}`

**Ожидаемый результат:**

- статус 200
- в ответе есть `accessToken` и `refreshToken` в формате JWT (три части через точку)
- `id` = 1, `username` = `emilys`
- в ответе нет поля `password`
- access-токен выдан на 60 минут (значение по умолчанию)

### TC-2. Вход с неправильным паролем
**Данные:**

POST /auth/login, тело `{"username":"emilys","password":"wrongpass"}`

**Ожидаемый результат:**

- статус 400
- "message": "Invalid credentials"

### TC-3. Вход с неправильным логином
**Данные:**

POST /auth/login, тело `{"username":"wrongname","password":"emilyspass"}`

**Ожидаемый результат:**

- статус 400
- "message": "Invalid credentials"

### TC-4. Вход с пустыми параметрами
**Данные:**

- пустое тело `{}`
- нет пароля
- нет логина
- пустой пароль
- пустой логин
- пустые строки

**Ожидаемый результат:**

- статус 400
- "message": "Username and password required"

### TC-5. Граничные значения expiresInMins

Допустимый диапазон: 1–43200 минут (максимум назван в сообщении об ошибке сервиса).
Во всех подкейсах: POST /auth/login, `username` = `emilys`, `password` = `emilyspass`, меняется только `expiresInMins`.
Время жизни токена проверяется по полям `exp - iat` в access-токене.

#### TC-5.1. expiresInMins = 1
**Ожидаемый результат:**

- статус 200
- access-токен выдан на 1 минуту

#### TC-5.2. expiresInMins = 43200
**Ожидаемый результат:**

- статус 200
- access-токен выдан на 43200 минут (30 дней)

#### TC-5.3. expiresInMins = 43201
**Ожидаемый результат:**

- статус 400
- "message": "Maximum access token expire time can be 43200 minutes"

**Связанный баг:** BUG-2

#### TC-5.4. expiresInMins = 0
**Ожидаемый результат:**

- статус 400
- сообщение о недопустимом значении expiresInMins

**Связанный баг:** BUG-1

#### TC-5.5. expiresInMins = -5
**Ожидаемый результат:**

- статус 400
- сообщение о недопустимом значении expiresInMins

**Связанный баг:** BUG-3

#### TC-5.6. expiresInMins = "abc"
**Ожидаемый результат:**

- статус 400
- сообщение о том, что expiresInMins должен быть числом

**Связанный баг:** BUG-4

## GET /auth/me — текущий пользователь

### TC-6. Получение профиля по корректному токену
**Предусловия:** выполнен вход (TC-1), получен `accessToken`

**Данные:** GET /auth/me с заголовком `Authorization: Bearer <accessToken>`

**Ожидаемый результат:**

- статус 200
- `id` = 1, `username` = `emilys`
- в ответе нет поля `password`

**Связанный баг:** BUG-5

### TC-7. Получение профиля по неправильному токену
**Предусловия:** для последних двух вариантов выполнен вход (TC-1), получены токены

**Данные:** GET /auth/me с заголовком `Authorization: Bearer <токен>`, где токен:

- произвольная строка: `garbage`
- строка в формате JWT, но не токен: `abc.def.ghi`
- настоящий access-токен с изменёнными последними символами (испорченная подпись)
- refresh-токен вместо access-токена

**Ожидаемый результат:**

- статус 401
- сообщение об ошибке авторизации
- данные пользователя не возвращаются

**Связанные баги:** BUG-6, BUG-7, BUG-8

### TC-8. Получение профиля без токена
**Данные:** GET /auth/me без заголовка `Authorization` и без cookies

**Ожидаемый результат:**

- статус 401
- "message": "Access Token is required"

## POST /auth/refresh — обновление токенов

### TC-9. Обновление по корректному refresh-токену
**Предусловия:** выполнен вход (TC-1), получен `refreshToken`

**Данные:** POST /auth/refresh, тело `{"refreshToken":"<refreshToken>"}`

**Ожидаемый результат:**

- статус 200
- в ответе новая пара `accessToken` и `refreshToken` в формате JWT
- новый `accessToken` работает в GET /auth/me (статус 200, `username` = `emilys`)

### TC-10. Обновление по некорректному refresh-токену
**Данные:** POST /auth/refresh, где `refreshToken`:

- не передан: тело `{}`
- произвольная строка: `garbage`
- access-токен вместо refresh-токена

**Ожидаемый результат:**

- статус 401 (не передан) или 403 (невалидный)
- сообщение об ошибке: "Refresh token required" или "Invalid refresh token"
- новые токены не выдаются

**Связанный баг:** BUG-9

## Найденные баги

### BUG-1. expiresInMins = 0 выдаёт токен на 30 дней вместо ошибки
**Шаги:** POST /auth/login с `{"username":"emilys","password":"emilyspass","expiresInMins":0}`

**Ожидаемый результат:** 400, значение вне допустимого диапазона 1–43200

**Фактический результат:** 200, токен со сроком жизни 43200 мин

**Серьёзность:** Major — клиент просит короткоживущий токен, а получает токен на максимальный срок

### BUG-2. expiresInMins больше максимума — ошибка сервера вместо ошибки валидации
**Шаги:** POST /auth/login с `{"username":"emilys","password":"emilyspass","expiresInMins":43201}`

**Ожидаемый результат:** 400, "Maximum access token expire time can be 43200 minutes"

**Фактический результат:** 500 с тем же сообщением

**Серьёзность:** Minor — сообщение верное, но код 500 означает необработанную ошибку на сервере

### BUG-3. Отрицательный expiresInMins — ошибка сервера с неверным сообщением
**Шаги:** POST /auth/login с `{"username":"emilys","password":"emilyspass","expiresInMins":-5}`

**Ожидаемый результат:** 400, сообщение о недопустимом значении

**Фактический результат:** 500, "Maximum access token expire time can be 43200 minutes" — сообщение про максимум, хотя значение меньше минимума

**Серьёзность:** Minor

### BUG-4. Нечисловой expiresInMins — ошибка сервера с неверным сообщением
**Шаги:** POST /auth/login с `{"username":"emilys","password":"emilyspass","expiresInMins":"abc"}`

**Ожидаемый результат:** 400, сообщение о том, что значение должно быть числом

**Фактический результат:** 500, "Maximum access token expire time can be 43200 minutes"

**Серьёзность:** Minor

### BUG-5. GET /auth/me возвращает пароль пользователя открытым текстом
**Шаги:** войти (TC-1), выполнить GET /auth/me с `Authorization: Bearer <accessToken>`

**Ожидаемый результат:** в ответе нет поля `password`

**Фактический результат:** в ответе `"password": "emilyspass"`

**Серьёзность:** Critical — утечка учётных данных

### BUG-6. Токен неверного формата — ошибка сервера вместо 401
**Шаги:** GET /auth/me с `Authorization: Bearer abc.def.ghi`

**Ожидаемый результат:** 401, сообщение об ошибке авторизации

**Фактический результат:** 500, "invalid token"

**Серьёзность:** Minor

### BUG-7. Токен с испорченной подписью — ошибка сервера вместо 401
**Шаги:** войти (TC-1), изменить последние символы `accessToken`, выполнить GET /auth/me с этим токеном

**Ожидаемый результат:** 401, сообщение об ошибке авторизации

**Фактический результат:** 500, "invalid signature"

**Серьёзность:** Minor — подделка отклоняется, но не тем кодом

### BUG-8. Refresh-токен принимается вместо access-токена
**Шаги:** войти (TC-1), выполнить GET /auth/me с `Authorization: Bearer <refreshToken>`

**Ожидаемый результат:** 401

**Фактический результат:** 200, данные пользователя

**Серьёзность:** Major — долгоживущий refresh-токен даёт доступ к данным как access-токен

### BUG-9. Access-токен принимается вместо refresh-токена
**Шаги:** войти (TC-1), выполнить POST /auth/refresh с `{"refreshToken":"<accessToken>"}`

**Ожидаемый результат:** 403, "Invalid refresh token"

**Фактический результат:** 200, выдана новая пара токенов

**Серьёзность:** Major — утёкший access-токен можно бесконечно продлевать
